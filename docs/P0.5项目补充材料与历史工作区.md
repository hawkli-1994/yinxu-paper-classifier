# P0.5 项目补充材料与历史工作区

## 产品边界

- 一篇主论文对应一个 Project。
- 一个 Project 可以有多份辅助材料、多个 Classification Run 和多个 Result Revision。
- Session 是每次 Classification Run 内部的 Pi Agent 会话，不在左侧作为一级对象展示。
- 左侧只展示论文项目；“规则与记忆”和“设置”是跨项目公共功能。
- 右侧项目工作区包含“资料”“AI 分类”“复核与导出”“历史版本”四个标签页。
- P0.5 是单人单机版本，一次只运行一个 AI 分类任务，不做批量导入和多人协同。

## 补充材料

新建项目时可以在选择一篇主论文 PDF 的同时：

- 多选 PDF、TXT、Markdown 辅助文件；
- 为每份文件标记“作者信息、书目信息、专家意见、论文附录/补扫、其他材料”；
- 填写来源或提供者；
- 添加一条手工补充说明。

项目创建后，可在“资料”继续添加文件或手工说明。移除采用软删除：材料不再进入新的分类运行，但原文件、材料 ID 和哈希仍保留，供旧运行审计。

补充材料只属于当前项目。它可以帮助核对作者、书目或理解专家意见，但不能伪装成论文正文页码证据。主分类引用仍必须来自主论文逐页文本。

## 分类运行与结果版本

每次点击“新建分类运行”都会创建独立 Run，记录：

- Provider、模型、思考等级；
- 分类知识包版本和 OCR 模型；
- 当次启用的补充材料 ID 与 SHA-256；
- 汇总后的补充材料只读文本快照；
- 独立的 Pi Agent Session 目录；
- 运行状态、开始时间、完成时间和失败原因。

AI 输出会生成一个 `agent` 结果版本；每次人工复核会生成一个 `review` 结果版本，并指向其父版本。项目只记录“当前激活版本”，不会覆盖或删除旧版本。用户可以在“历史版本”中把任意旧版本重新设为当前结果。

## 本地目录

```text
projects/<projectId>/
├── project.json
├── source/original.pdf
├── extracted/
├── supplements/
│   ├── manifest.json
│   ├── files/
│   ├── notes/
│   └── extracted/
├── runs/<runId>/
│   ├── run.json
│   ├── supplement-context.md
│   └── session/
├── revisions/
│   ├── manifest.json
│   └── <revisionId>.json
└── result/
```

`result/` 保留兼容性的当前结果副本；审计和版本切换以 `revisions/` 为准。旧版项目首次打开时，已有结果会迁移为一个 Legacy Run 和一个结果版本。

## 后续演进

项目级 Agent 对话适合在后续版本加入。届时聊天应依附于某个 Project，并明确选择基于哪个 Result Revision 开始；Agent 的修改先形成候选变更，用户确认后再生成新的 Result Revision。这样可以支持自然语言微调，同时维持“可解释、可撤回、不覆盖旧结果”的边界。
