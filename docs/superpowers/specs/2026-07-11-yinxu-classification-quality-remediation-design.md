# 殷墟论文分类质量整改设计

> 2026-07-13 OCR 最终修订：所有 PDF 统一使用 PaddleOCR 官方托管 API、官方 TypeScript SDK 与 `PaddleOCR-VL-1.6` 文档解析；无 AI Studio Access Token 或云端任务失败时不得回退到本地文本层。

## 背景与目标

本设计落实 2026-07-11 对现有 Skill 与工作流的审查结论。目标不是继续扩展界面，而是把当前“能运行的流程骨架”升级为具备可核验证据、确定性后处理和可纠错人审闭环的单机分类工具。

原始方法以《社科院殷墟论文完整分类整理方案》和《殷墟论文分类整理模板》为准：4 个一级类、16 个二级类、72 个三级类、论文 A-Z 26 字段，以及材料优先、研究主题次之、数字化优先检查 D2、甲骨与考古交叉按核心论证材料确定主类等规则。

## 质量原则

1. 模型负责提取、比较和解释；程序负责不可绕过的结构校验、路径一致性、页码证据和置信度。
2. 每一页 OCR 文本只能属于该页，不允许整篇 OCR 文本复制到多个页码。
3. 主分类必须经过“核心材料 -> 文献性质 -> 主要研究问题 -> 易混类别仲裁”四步。
4. 不能从文本证明的视觉复原字段必须留空并标红，不能靠常识补全。
5. 学生必须能够修改主分类、互见分类、证据和普通字段；保存后重新校验。
6. 每次运行只加载殷墟分类 Skill，避免本机其他 Skill 干扰。
7. 知识包路径和版本只能来自 `VERSION`，不得在运行链路中硬编码。

## Skill 结构

知识包调整为：

```text
resources/yinxu-classifier/
├── SKILL.md
├── VERSION
├── taxonomy.json
├── paper-schema.json
├── special-rules.json
└── references/
    ├── classification-rules.md
    ├── field-guidance.md
    └── classification-examples.md
```

`SKILL.md` 只保留严格执行顺序和资源路由。它必须要求 Agent：

1. 读取全部文本分块，不得只读首段；
2. 读取分类规则、字段指南和示例；
3. 先提取可核验事实，再产生候选；
4. 对照易混类别矩阵进行排除；
5. 为主分类和关键字段提供逐页证据；
6. 输出草稿 JSON，不得自报最终置信度。

`classification-rules.md` 承载层级决策树、主类/互见规则、院内作者、资料整理/研究论述、专著析出文献和易混类别矩阵。`field-guidance.md` 定义 26 字段的允许值、证据要求和禁止猜测项。`classification-examples.md` 提供覆盖主要冲突对的正反例。

`special-rules.json` 改为可被程序和测试读取的结构化规则清单；每条包含 `id`、`priority`、`when`、`prefer`、`crossReference` 和 `rationale`。

## 文本与 OCR

PDF.js 与 MuPDF 只负责页数检查和文本层质量对照。所有 PDF 均整份提交给 PaddleOCR 官方托管文档解析 API，官方服务返回的逐页 Markdown 是分类流程的权威文本。`writeExtractedText` 同时生成：

- `text.jsonl`：逐页权威文本；
- `full-text.md`：带页码注释的全文；
- `chunks/chunk-NNNN.md`：不超过约 20,000 字符的完整分块；
- `report.json`：每页来源、字符数和整体 OCR 质量。

应用通过 `@paddleocr/api-sdk` 调用 `PaddleOCR-VL-1.6`，启用版面检测、图表识别和 Markdown 整理。返回页必须与原 PDF 页数和顺序一致；任一页面包含控制符、明显重复或低质量文本时停止导入或标记人工复核。模型和服务地址均由产品固定，用户只配置 AI Studio Access Token。

## Agent 草稿与确定性后处理

Agent 写入的 `agent-result.json` 是草稿，包含：

- 26 字段；
- 主分类、互见分类；
- 至少两个候选及比较理由；
- 主分类证据；
- 规则冲突；
- 摘要；
- 每个字段的分数、理由和证据。

草稿先经 Ajv 完整 Schema 校验，再进入规范化：

- 根据 `primaryCategoryCode` 强制覆盖一、二、三级分类字段；
- `文件路径` 强制设为 `source/original.pdf`；
- 删除重复或与主类相同的互见分类；
- 校验候选代码和分数；
- 校验证据是否存在于指定页；
- 为缺失或无证据字段生成红色评估；
- 根据 OCR、证据、候选差距、规则冲突和关键元数据计算最终置信度；
- `reviewStatus` 强制为 `needs_review`。

规范化结果由主进程原子写入，不依赖 Agent 自行完成最终文件写入的正确性。

## 人工复核

复核页提供：

- 可搜索的 72 个三级主分类选择器；
- 最多三个互见分类多选器；
- 每个字段的绿/黄/红状态和证据；
- 可编辑的页码、引文和理由；
- 当前证据页 PDF 预览；
- 重新计算后的整篇置信度。

保存时主进程重新执行规范化和校验。存在非法分类、不可核验证据或缺失关键元数据时不得确认。人工修改记录写入结果并随 Excel 导出。

## 知识包隔离与版本

`ensureKnowledgePackage` 返回 `{ path, version }`。该对象传给 IPC 注册与项目创建。Pi `DefaultResourceLoader` 使用 `noSkills: true`，只通过 `additionalSkillPaths` 注入本知识包。

## 导出与审计

Excel 保留 A-Z 顺序和完整三级目录；处理说明增加模型、知识版本、OCR 质量、候选、互见、规则冲突、证据和人工修改记录。图像素材库恢复模板的 18 个字段（含备注）。视觉分析未实现前保持空表，避免伪造图像资产信息。

## 测试与质量门槛

自动测试覆盖：

- 72 类目录与结构化规则完整性；
- 完整 Schema 的正反例；
- 单页 OCR 映射，不允许跨页复制；
- 长文分块覆盖全部页；
- 分类路径和文件路径确定性覆盖；
- 程序置信度覆盖模型输入；
- 只加载一个分类 Skill；
- 主分类、互见和证据可编辑并保存；
- Excel 审计字段和图像素材库表头。

另提供黄金集评估入口。实际准确率门槛必须在用户提供或专家标注 30-50 篇代表性论文后确定；在此之前不能声称已达到社科院专业分类准确率。
