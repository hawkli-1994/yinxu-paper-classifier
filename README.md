# 殷墟论文分类助手

面向学生的 Windows 单机版殷墟研究论文分类工具。它将 PDF 导入为独立本地项目，使用 Pi Agent 编排提取、分类与校验，并按社科院殷墟论文分类目录导出 Excel。

## 当前 V0.5 能力

- 一篇论文对应一个本地论文项目，可在左侧项目列表中搜索、切换和重新打开；
- 新建项目时只选择一篇主论文，同时可选择多份 PDF、TXT、Markdown 补充材料或填写手工说明；
- 项目创建后仍可在“资料”中增补或移除作者信息、书目信息、专家意见、论文附录和其他材料；
- 检测低文本页面，配置 OCR 后调用 PaddleOCR-VL-1.5（自动转 PNG）或 DeepSeek-OCR；
- 使用 Pi 支持的 Provider 与模型完成分类编排；
- 内置 4 个一级、16 个二级、72 个三级分类；
- 生成 26 个论文分类字段、主分类、互见分类、证据和置信度；
- 每个项目可建立多次 AI 分类运行；每次运行使用独立 Pi Agent 会话，并保存当次模型、知识包和补充材料只读快照；
- 人工修改并保存复核结果；AI 结果与每次人工复核都生成不可覆盖的历史版本，可随时切回旧版本；
- 设置长期有效的个人规则提示词，并按论文内容检索已批准规则和相似复核记录；
- 每次人工复核在本机追加原始反馈，可选择生成“候选规则”；候选规则必须由用户批准后才会生效；
- 作者姓名和署名单位只按当前论文原文记录，不按静态名单推断院内外身份；作者信息反馈不会生成分类规则或注入后续 Agent 上下文；
- 在“规则与记忆”中创建、编辑、启停、回滚、删除和导出个人规则，批准或驳回候选规则；
- 检测互相矛盾的个人规则，将冲突写入结果、降低置信度并要求人工复核；
- 导出 `论文分类结果`、`三级分类目录`、`处理说明`、`图像素材库` 四个工作表；
- 每篇论文在本机独立项目目录中保存输入、提取文本、补充材料、分类运行、Agent 会话和结果版本；全局同时只运行一个 AI 分类任务。

## 学生使用流程

1. 打开“设置”。
2. 输入 Pi Provider、模型 ID 与该 Provider 的 API Key。
3. 配置扫描件 OCR：默认服务地址为 `https://api.siliconflow.cn/v1`，默认模型为 `PaddlePaddle/PaddleOCR-VL-1.5`；该模型会在本机将待识别 PDF 页转换为 PNG 后调用。
4. 点击“新建论文项目”，选择一篇主论文 PDF；需要时同时添加多份辅助文件或手工补充说明。
5. 在项目的“资料”中核对主论文与补充材料；以后获得新材料也可以回到这里继续添加。
6. 进入“AI 分类”，点击“新建分类运行”。同一项目可以多次运行，旧结果不会被覆盖。
7. 在“设置”中按需填写长期个人分类偏好；具体规则可以在“规则与记忆”中维护。
8. 在“复核与导出”检查黄色或红色结果，填写问题类型和修改理由，再保存人工修改。
9. 若选择“生成候选规则”，到“规则与记忆”批准或驳回；未批准的候选不会影响后续分类。
10. 在“历史版本”查看分类运行和结果版本，必要时切回旧版本；确认后导出 Excel。

API Key 仅发送到 Electron Main Process，并通过当前 Windows 用户的系统安全存储保护；不会写入 Excel 或论文项目文件。

## 本地开发

开发机需要 Node.js。学生安装包不需要额外安装 Node.js、Python、Docker 或开发工具。

```bash
npm install
npm run dev
```

验证：

```bash
npm run test:run
npm run typecheck
npm run test:e2e
```

Windows 构建：

```bash
npm run package:win
```

该命令输出 NSIS 安装程序与 portable 可执行文件到 `release/`。

## 数据位置

Windows 中项目默认保存于：

```text
%APPDATA%/殷墟论文分类助手/
```

卸载应用不会自动删除论文项目。

每个项目位于 `projects/<projectId>/`：主论文在 `source/`，补充材料及清单在 `supplements/`，每次分类及其 Agent 会话在 `runs/`，不可覆盖的结果版本在 `revisions/`。个人规则、候选规则、反馈记录和记忆导出分别保存在应用数据目录的 `memory/` 与 `exports/` 中。数据不在电脑之间同步。

## 反馈学习边界

V0.5 实现的是可审计的 Agent 反馈循环，不是直接更新大模型权重的在线强化学习：

1. 人工复核保存“原结果、修正结果、错误类型、理由”；
2. 系统把复核经验转成候选规则；
3. 用户批准后，规则才进入后续分类的检索上下文；
4. 后续人工接受或改正分类，会更新已命中规则的应用次数、接受次数和经验可信度；
5. 个人记忆不能覆盖论文原文、专家分类体系、结构化输出和证据要求。

作者姓名、署名单位和机构身份属于元数据，不是主题分类依据。当前版本不建设学者权威库，不根据姓名推断当前单位；相关 P0 规则见 [`docs/社科院殷墟论文分类方案-P0作者信息修订.md`](docs/社科院殷墟论文分类方案-P0作者信息修订.md)。

## 当前限制

- V0.5 仍是单人单机工具，不提供班级共享、教师后台或云同步；
- 一个项目只允许一篇主论文，不提供批量导入；
- 项目级 Agent 对话与通过对话微调结果尚未纳入 V0.5；当前通过重复分类、人工复核和版本切换完成迭代；
- 图像素材库工作表目前作为空模板导出，不自动提取论文图片；
- Agent 保留 Pi 默认工具能力，首版不实现权限审批或沙箱；
- 扫描 PDF 的 OCR 依赖网络与学生自己的 OCR API Key；
- 论文上传到所选 Agent/OCR Provider 前，使用者应确认拥有相应授权。
